# Власний блокчейн з нуля (практичне заняття 1)

Невелика криптовалюта на TypeScript без готових блокчейн-платформ: гаманці з підписами Ed25519, мемпул, дерево Меркла, Proof of Work з автоматичною складністю, ланцюг із повною перевіркою, мережа вузлів по HTTP із вибором ланцюга за сумарною роботою, консольне керування. Додатково: «легкий» клієнт із доказом Меркла і запуск п'яти вузлів через Docker Compose.

## Вимоги

- Node.js **22.18 або новіший** (запускає `.ts`-файли напряму, без збірки). Перевірка: `node -v`.
- Для додаткового завдання з Docker: Docker Desktop.
- Залежностей часу виконання немає. `npm install` ставить лише TypeScript і типи для перевірки коду.

## Запуск трьох вузлів

```
npm install
npm run network
```

Піднімаються три окремі процеси на портах 3001, 3002, 3003. Лог кожного позначений його портом. Зупинка: `Ctrl+C`.

Щоб блоки знаходились швидко, можна задати меншу складність генезису (однакову для всіх вузлів і для консолі):

```
# PowerShell
$env:GENESIS_DIFFICULTY=12; npm run network
# cmd
set GENESIS_DIFFICULTY=12 && npm run network
```

Дані вузлів лежать у `data/<порт>/`, гаманці майнерів у `wallets/node1.json`, `node2.json`, `node3.json` (обидві папки не потрапляють у репозиторій). Щоб почати з чистого листа, видаліть ці папки. Кількість вузлів змінюється змінною `NODES` (наприклад, `$env:NODES=5`).

## Керування вузлом (консоль)

Другий термінал, та сама папка проєкту. Адресу вузла задає `--node` (за замовчуванням `http://localhost:3001`).

| Команда                                                                                                 | Що робить                                                           |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `node src/cli.ts wallet create --wallet wallets/my.json`                                                | створити гаманець (ключі зберігаються у файлі)                      |
| `node src/cli.ts wallet show --wallet wallets/my.json`                                                  | показати адресу                                                     |
| `node src/cli.ts send <адреса> <сума> --fee 2 --wallet wallets/node1.json --node http://localhost:3001` | надіслати транзакцію (nonce береться автоматично)                   |
| `node src/cli.ts mine --node http://localhost:3001`                                                     | намайнити блок                                                      |
| `node src/cli.ts chain --node http://localhost:3001`                                                    | показати ланцюг (`--full` повний JSON)                              |
| `node src/cli.ts balance <адреса> --node http://localhost:3001`                                         | баланс адреси                                                       |
| `node src/cli.ts mempool --node http://localhost:3001`                                                  | транзакції в черзі                                                  |
| `node src/cli.ts validate --node http://localhost:3001`                                                 | повна перевірка ланцюга                                             |
| `node src/cli.ts add-peer <url> --node http://localhost:3001`                                           | додати сусіда                                                       |
| `node src/cli.ts sync --node http://localhost:3001`                                                     | синхронізуватися з мережею                                          |
| `node src/cli.ts offline` / `online --node http://localhost:3003`                                       | відключити / підключити вузол (для демонстрації форку)              |
| `node src/cli.ts verify-tx <id> --node http://localhost:3001`                                           | «легкий» клієнт: перевірити доказом Меркла, що транзакція є в блоці |
| `node src/cli.ts help`                                                                                  | повний список команд                                                |

Керувати вузлом можна і напряму через HTTP (REST): маршрути описані в `src/node/server.ts` (`/status`, `/mine`, `/balance/<адреса>`, `/chain/local`, `/validate`, `/sync`, `/peers`, `/headers`, `/proof/<id>` та інші).

## Демонстрація розгалуження (PowerShell)

Мережа з `npm run network` запущена. Другий термінал (якщо мережа запущена з `GENESIS_DIFFICULTY=12`, задайте її й тут):

```
node src/cli.ts mine --node http://localhost:3001
$addr2 = (Get-Content wallets/node2.json | ConvertFrom-Json).address

node src/cli.ts offline --node http://localhost:3003
node src/cli.ts send $addr2 10 --fee 2 --wallet wallets/node1.json --node http://localhost:3001
node src/cli.ts mine --node http://localhost:3001
node src/cli.ts mine --node http://localhost:3003
node src/cli.ts mine --node http://localhost:3003

node src/cli.ts online --node http://localhost:3003
node src/cli.ts sync --node http://localhost:3001
node src/cli.ts mempool --node http://localhost:3001
node src/cli.ts validate --node http://localhost:3001
```

Очікувано: вузол 1 переходить на ланцюг вузла 3 (у ньому більше сумарної роботи), а транзакція з відкинутого блоку повертається в мемпул вузла 1 (рядок «відкинуто блоків 1, транзакцій повернуто в мемпул 1»).

## Тести, атаки, експеримент

```
npm run check        # перевірка типів TypeScript (нічого не виводить, якщо все гаразд)
npm test             # автоматичні тести, усі мають пройти
npm run attacks      # п'ять атак зі списку завдання і реакція системи
npm run experiment   # час майнінгу від складності; результат у results/ (CSV і графік SVG)
```

Параметри експерименту (необов'язково): `EXPERIMENT_BITS="8,12,16,20"` (рівні складності в бітах), `EXPERIMENT_RUNS=30` (запусків на рівень, мінімум 10).

## Docker Compose (п'ять вузлів)

```
docker compose up --build
```

Вузли доступні на портах 3001–3005 (`node1` … `node5`), працюють у контейнерах. Керування з комп'ютера: `node src/cli.ts ... --node http://localhost:3004`. Зупинка: `Ctrl+C`, потім `docker compose down` (`docker compose down -v` також видаляє збережені ланцюги). Складність генезису в `docker-compose.yml` дорівнює 12; для консольних команд задайте `$env:GENESIS_DIFFICULTY=12`.

| `src/core/mempool.ts`                                     | черга транзакцій із чотирма перевірками (підпис, баланс, nonce, дублікати) |

| `src/core/pow.ts`, `difficulty.ts`, `miner.ts`, `work.ts` | Proof of Work, коригування складності, складання блока, сумарна робота     |
| `src/core/blockchain.ts`, `storage.ts`                    | ланцюг, баланси, повна перевірка, збереження у файл                        |

| `scripts/`                                                | запуск мережі, атаки, експеримент                                          |

| `Dockerfile`, `docker-compose.yml`                        | запуск п'яти вузлів у Docker                                               |

## Ухвалені рішення

- Модель рахунків (баланс на адресі); адреса це SHA-256 від байтів публічного ключа. Підпис Ed25519 (вбудований у Node.js).
- Сума і комісія цілі числа. Усі значення, що хешуються чи підписуються, записуються канонічно (ключі за алфавітом, без пробілів).
- Складність виміряна в **нульових бітах** хешу (один hex-нуль це 4 біти, тому 4 біти це ×16 за часом). Так коригування складності відбувається плавніше, ніж цілими hex-нулями.
- Складність змінюється на ±1 біт кожні K = 10 блоків залежно від того, швидше чи повільніше за 10 секунд на блок ішли блоки.
- Вибір ланцюга за сумарною роботою (сума 2^складність по блоках), при рівній роботі вузол лишається на своєму.
- Майнінг запускається командою, а не безперервно.
